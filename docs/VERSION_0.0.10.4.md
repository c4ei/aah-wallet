# IEUM Wallet 0.0.10.4 변경 내역

## 완료

- Windows Normal의 SQLite 링크 방식을 체인 0.21.5의 정적 링크와 일치시켰다.
- Actions 기본 Core를 `v0.21.5`로 고정하고 실제 Cargo 버전을 검사한다.
- Wallet 표시 버전은 `0.0.10.4`, Cargo/npm/Tauri 내부 버전은 `0.0.10-4`로 변경했다.
- Normal에 포함된 Core는 이미 libp2p relay server/client를 실행하므로 PC가 NAT 중계 거점으로 참여할 수 있다.
- 체인 보상 후보는 최소 1시간 연속 가동과 서로 다른 3개 피어의 실제 중계 영수증을 모두 요구한다.
- Normal 노드 장기 보상 총량은 210,000,000 IEUM(2억 1천만 개), 종료는 2040년,
  매년 50% 반감 곡선으로 고정했다.
- 현재 운영 높이 0을 반영해 높이 100과 `2026-08-10 00:00:00 KST`를 모두 충족해야
  보상 정책이 활성화된다.
- 메인 4노드는 일일 총예산 안에서 일반 노드의 1.5배 가중치를 받도록 설계했다.
- 거래 수수료 중 기존 20% 재단 배분 규칙을 유지했다.

## 보상 설계

단순히 프로그램을 1시간 켜는 것만으로 지급하면 다중 VM 공격이 가능하다. 따라서 1시간은 자격의 시작일 뿐이며 실제 트래픽 중계, 중복 제거된 메시지, 독립 검증 피어가 있어야 후보가 된다. PoW 계산이나 고전력 채굴은 하지 않는다.

## 차후 작업

- 운영 메인 4노드의 PeerId를 체인 정책 파일에 입력
- 중계 영수증을 gossipsub로 수집해 확정 블록의 시스템 이벤트로 정산하는 런타임 연결
- 지급 주소를 Normal 월렛 주소로 서명 등록하는 UI와 RPC
- 누적 지급량을 체크포인트 상태에 포함하고 210,000,000 IEUM 상한을 합의 검증
- 실제 GitHub runner에서 Light/Normal/Android 전체 작업 및 updater `latest.json` 확인
- 운영 활성화 높이와 기존 운영 제네시스 공급량의 회계 처리 확정

보상 곡선·자격·일일 배분 계산은 0.21.5에 포함된다. 다만 중계 영수증 서명 전파와
누적 지급량의 합의 상태 저장이 끝나기 전에는 실제 IEUM 자동 발행을 활성화하지 않는다.
