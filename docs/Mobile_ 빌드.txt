Android 빌드

Ubuntu VM에서도 가능해. Android Studio를 설치한 후 SDK Manager에서 다음을 설치해.

Android SDK Platform
Android SDK Build-Tools
Android SDK Platform-Tools
Android SDK Command-line Tools
Android NDK
CMake

환경변수 설정 예시:

export JAVA_HOME=/usr/lib/jvm/java-17-openjdk-amd64
export ANDROID_HOME="$HOME/Android/Sdk"
export NDK_HOME="$ANDROID_HOME/ndk/설치된_NDK_버전"

export PATH="$PATH:$ANDROID_HOME/platform-tools"
export PATH="$PATH:$ANDROID_HOME/cmdline-tools/latest/bin"

확인:

java -version
adb version
ls "$NDK_HOME"

프로젝트에서 Android 구조를 최초 한 번 생성해.

cd ~/www/aah-wallet

npm install
npm run tauri android init

휴대폰 테스트는 USB 디버깅을 켜고 연결한 다음:

adb devices
npm run tauri android dev

에뮬레이터를 먼저 실행해도 돼.

배포용 빌드:

npm run tauri android build

결과물은 보통 다음 경로 아래에 생겨.

src-tauri/gen/android/app/build/outputs/apk/
src-tauri/gen/android/app/build/outputs/bundle/
APK: 휴대폰 직접 설치·테스트
AAB: Google Play 등록

서명되지 않은 APK라면 개발 확인용으로는 다음처럼 설치할 수 있어.

adb install -r 경로/app-universal-release-unsigned.apk

Google Play 배포용 AAB는 별도의 Android 서명 키를 만들어 Gradle 서명 설정을 해야 해. 서명 키와 비밀번호는 GitHub에 올리면 안 돼.

iPhone/iOS 빌드

iOS는 Ubuntu나 Windows에서 최종 빌드할 수 없어. 다음 환경이 필요해.

macOS
Xcode
Apple ID
실제 iPhone 설치 또는 App Store 등록 시 Apple Developer 계정
Xcode Command Line Tools

Mac에서:

xcode-select --install

cd ~/www/aah-wallet
npm install
npm run tauri ios init

시뮬레이터 실행:

npm run tauri ios dev

배포 빌드:

npm run tauri ios build

서명이나 기기 선택이 필요하면 생성된 Xcode 프로젝트를 열어 설정해.

open src-tauri/gen/apple/aah-wallet.xcodeproj

Xcode의 Signing & Capabilities에서 다음을 지정해야 해.

Team
Bundle Identifier: net.aah.wallet
Signing Certificate
Provisioning Profile

App Store 제출은 Xcode에서:

Product → Archive → Distribute App

순서로 진행하면 돼.

현재 지갑에서 주의할 점

실제 휴대폰에서는 RPC 주소를 이렇게 쓰면 안 돼.

http://127.0.0.1:8545
http://localhost:8545

휴대폰에서 localhost는 휴대폰 자신이기 때문이야. 개발 중에는 서버의 내부 IP를 사용해야 해.

http://192.168.0.100:8545

공개 배포에서는 반드시 HTTPS RPC가 좋아.

https://rpc.aah.name

또한 현재 open_aah_site는 데스크톱용 별도 창을 생성하므로 모바일에서는 다음처럼 바꾸는 것이 안전해.

PC: IPC가 차단된 별도 앱 창
Android/iOS: 시스템 브라우저 또는 모바일 전용 웹뷰

따라서 바로 android init을 시도할 수는 있지만, 다음 작업본에서는 모바일 분기와 버전 통일을 먼저 반영해야 안정적으로 Android/iOS를 함께 지원할 수 있어. 공식 절차는 Tauri 2 개발 문서를 기준으로 하면 돼.





윈도우 PC용도 가능해. 다만 Windows용 .exe/.msi 설치 파일은 Windows PC에서 빌드하는 게 가장 확실해.

필요한 프로그램:

Node.js LTS
Rust
Microsoft Visual Studio 2022 Build Tools
Desktop development with C++
Windows 10/11 SDK
Microsoft Edge WebView2 Runtime

PowerShell에서 설치와 확인:

winget install OpenJS.NodeJS.LTS
winget install Rustlang.Rustup
winget install Microsoft.VisualStudio.2022.BuildTools
winget install Microsoft.EdgeWebView2Runtime

설치 후 PowerShell을 다시 열고:

node --version
npm --version
rustc --version
cargo --version

소스를 받은 뒤 개발 실행:

git clone https://github.com/c4ei/aah-wallet.git
cd aah-wallet

npm install
npm run tauri dev

Windows 설치 파일 생성:

npm run tauri build

결과물은 일반적으로 여기에 생성돼:

src-tauri\target\release\bundle\msi\
src-tauri\target\release\bundle\nsis\
MSI: Windows Installer 설치 파일
NSIS EXE: 일반적인 setup.exe 설치 파일

현재 PC가 ARM이 아닌 일반 Intel/AMD Windows라면 기본 빌드로 x86_64용이 생성돼.

서버 연결 시에는 Windows도 실제 RPC 주소를 설정해야 해.

https://rpc.aah.name

개발 서버가 같은 공유기 내부에 있다면:

http://192.168.x.x:8545

Windows Defender가 미서명 설치 파일에 경고를 표시할 수 있어. 내부 테스트에서는 실행할 수 있지만, 일반 사용자 배포에는 코드 서명 인증서로 .exe와 .msi를 서명하는 게 좋아.

정리하면 지원 구조는 다음과 같아.

플랫폼	빌드 환경	결과물
Windows	Windows 10/11	.exe, .msi
Linux	Ubuntu	.deb, .AppImage, .rpm
Android	Windows/Linux/macOS + Android SDK	.apk, .aab
iPhone	macOS + Xcode 필수	.ipa, App Store 빌드
macOS	macOS + Xcode	.app, .dmg

현재 v0.0.3.2 압축본도 Windows에서 위 절차로 개발 실행할 수 있어. 다만 Android/iOS까지 한 소스로 안정적으로 빌드하려면 앞서 말한 aah.name 열기 기능의 플랫폼 분기부터 반영하는 게 다음 작업이야.
