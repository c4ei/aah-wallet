# IEUM Wallet v0.0.5.0

## 적용 대상

- IEUM Chain `v0.18.0`
- 로컬 JSON-RPC `ieum_sendCommunication`, `ieum_pollCommunication`

## 구현 내용

- 친구의 지갑 주소와 PeerId 등록
- 친구 한 명을 선택하는 1:1 채팅
- 여러 친구에게 구성원별로 암호문을 전달하는 1:n 채팅
- 방을 만든 현재 사용자는 방장 1명
- 방장이 구성원을 부방장 또는 청중으로 지정
- AES-256-GCM, 메시지별 96비트 무작위 nonce
- 4,000자 제한, 체인 통신 암호문 90초 만료
- 수신 메시지는 현재 세션 화면에만 표시
- 메시지 평문, 음성, 영상은 블록과 원장에 저장하지 않음

## 사용 순서

1. 각 사용자가 자기 IEUM 노드를 실행합니다.
2. 노드 시작 로그의 `12D3KooW...` PeerId를 확인합니다.
3. 친구의 지갑 주소와 PeerId를 주소록에 등록합니다.
4. 1:1 상대 또는 1:n 그룹을 고릅니다.
5. 한 사용자가 64자리 방 보안 키를 생성합니다.
6. 보안 키를 직접 만나거나 이미 확인된 별도 보안 경로로 공유합니다.
7. 상대도 같은 보안 키를 입력한 뒤 메시지를 보냅니다.

RPC는 반드시 `127.0.0.1`에 바인딩해야 합니다. 체인 v0.18.0은 외부 IP로 RPC를
열면 통신 RPC를 비활성화합니다.

## 보안 경계

이 버전은 평문 대신 브라우저 WebCrypto의 AES-GCM을 사용합니다. 노드와 전달 peer는
메시지 본문을 읽을 수 없지만 통신 시각과 송수신 PeerId 메타데이터는 관찰할 수 있습니다.
방 키를 가진 사람은 메시지를 읽을 수 있으므로 구성원을 내보낸 뒤에는 반드시 새 방 키를
만들어야 합니다.

메인넷 또는 민감한 업무에 쓰기 전에는 다음 보강과 외부 보안감사가 필요합니다.

- 지갑 주소와 통신 키의 서명된 결합
- 1:1 Signal Double Ratchet 또는 동급 검증 프로토콜
- 그룹 MLS 기반 키 교체와 구성원 제거
- 운영체제 보안 저장소에 통신 키 보관
- 재전송·순서·키 변경 경고와 차단/신고

따라서 현재 버전을 “보안 문제가 절대 없는 완성형 메신저”로 간주하면 안 됩니다.
화상채팅은 WebRTC DTLS-SRTP, 카메라·마이크 권한, STUN/TURN 운영과 별도 감사가
필요하므로 이번 변경분에는 포함하지 않았습니다.
